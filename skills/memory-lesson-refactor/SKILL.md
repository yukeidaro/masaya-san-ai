# 記憶・レッスン構造の見直しスキル

学びを残すメモは自動で増えていくが、量が増えると古いもの・重複・矛盾が混ざり、肝心のルールが効かなくなる。
このスキルは **消さずに組み直す**。元のファイルは必ずバックアップしてから触る。

## 対象

- Claude Code：`~/.claude/CLAUDE.md`、各プロジェクトの `CLAUDE.md`、`~/.claude/projects/*/memory/`、`~/.claude/skills/`
- Codex：`~/.codex/AGENTS.md`、各プロジェクトの `AGENTS.md`
- その他、本人が「ここにレッスンを書いている」と指定したファイル

## 手順

1. **バックアップ**：対象ファイルを `~/ai-memory-backup/<日付>/` にコピーする。
2. **集める**：対象ファイルから、ルール・学び・注意書きを1件ずつ抜き出し、一覧にする（出典ファイルと行も残す）。
3. **今回のミスを特定する**：繰り返しているミスを1〜3行で書く。該当するレッスンが既にあるか探す。
   - ある → なぜ効いていないか（埋もれている、書き方があいまい、別のルールと矛盾、読まれない場所にある）を判定する
   - ない → 新しいレッスンを書く
4. **分類する**：全レッスンを次の4つに分ける。

   | 区分 | 置き場所 | 例 |
   | --- | --- | --- |
   | 毎回守る原則 | `CLAUDE.md` / `AGENTS.md` の先頭（10件以内） | 送信前に必ず確認する |
   | 特定の作業の手順 | その作業の **スキル**（`SKILL.md`） | メタ広告入稿のチェック項目 |
   | 事実・前提 | メモリ（`memory/`） | アカウント構成、命名ルール |
   | もう不要 | 削除候補（消さずに一覧で本人に見せる） | 終わった案件の注意 |

5. **書き直す**：レッスンを次の形に統一する。
   - **いつ**：どの作業のとき（例：メタ広告を入稿するとき）
   - **何をする**：具体的な行動（例：入稿前に予算・配置・除外オーディエンスの3項目を読み上げて確認）
   - **なぜ**：過去に起きたミス（1行）
   - 重複は1件にまとめ、矛盾するものは本人に確認する
6. **繰り返しミスはチェックリストにする**：2回以上起きたミスは、その作業のスキルの冒頭に「実行前チェック」として置く。
7. **報告する**：変更前後の件数、移動したレッスン、削除候補、本人に確認したい矛盾を一覧にする。**削除と矛盾の解消は承認を得てから** 反映する。

## やってはいけないこと

- バックアップなしで書き換える
- 本人の承認なしにレッスンを削除する
- 原則を増やしすぎる（先頭の原則は10件以内。増えたらスキルに移す）

## 使い方のコツ

- 同じミスが出たセッションの中で、そのまま「memory-lesson-refactor を使って」と頼むと、ミスの文脈を使って直せる
- 月に1回、定期タスクで「レッスンの棚卸し」を回すと詰まりにくい
