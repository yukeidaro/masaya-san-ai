## 4. 選択肢は3つ。結論は GAS

| 案 | 中身 | 評価 |
|---|---|---|
| 既製フォームを埋める | Google フォーム等 | 一番簡単。ただし**サイト内で完結しない** |
| **GAS** | コメント欄 → **スプレッドシートに蓄積** | **無料。今回の要件に一番合う** |
| Vercel で動的アプリ化 | 本格的な Web アプリ | **工数が重い**。全員がアクセスできてしまう |

**GAS（Google Apps Script）** … Google が無料提供しているスクリプト。
**Claude Code に作らせればいい**ので、実質的な作業は「お願いする」だけです。

→ Masaya さん:「**GAS 使うのアリかも。それが一番、僕の要件としては**」

## 4. 貯めたデータは、そのまま可視化に戻せる

- スプレッドシートのデータを **サイト側に戻して可視化することは可能**です。
- 反映は「**確認してから反映**」も「**自動で反映**」も選べます。
- 自動にするなら **Claude Code の「オートメーション」**：
  - 毎時 / 毎日◯時に取り込む
  - **入力があったタイミングで更新する**

**Yu の実例（本業）**
電話番号・メールが入力される → **GAS がスプレッドシートに全部転記** →
その内容を元に **各アドレスへカスタマイズしたメールを自動送信**。ここまで全自動。

→ Masaya さん:「**めっちゃいけそう感が出てきた**」

## 決定事項

- **Agent Teams は「効率」ではなく「質」のための道具**。依存関係のあるタスクには使わない。
- 採算シミュレーションは **「収集チーム（並列）→ 人の確認 → 分析＋批評チーム」** の2段構成で組む。
- Agent Teams は **`/agent-teams`** で作る。**Obsidian での管理は不要**。トークンが高いので常用しない。
- Claude Code は **Shift + Tab** でモード切替。**複雑なタスクはプランモード**。
- 切り抜きは**案で止めず、Remotion で完成物を出す**。
- **HTML 単体ではコメントを保存できない**。意見収集は **GAS ＋ スプレッドシート**で実装する。
- Vercel などの動的アプリ化・アクセス制限（認証）は**工数が重いので今はやらない**。
- 可視化への反映は **Claude Code のオートメーション**（定期実行 / 入力トリガー）で行う。
- UI/UX は **既存デザインのカタログから土台を選ぶ**。ゼロからの創作はデザイナーの領域。
- **次のテーマは「ナレッジ（メモリー）の蓄積」**。評価は Yu のプロンプトを走らせて判断する。

# まとめ

**今日の共通点は「一歩手前で止まっていた」ことです。**

切り抜きは**案**で止まっていた → **完成物**まで出す。
意見は**コピペ**で止まっていた → **貯める**。
ナレッジは**作りっぱなし**で止まっていた → **片付けるルーティンを持つ。**

Agent Teams も同じで、**速くするためではなく、一歩深く考えさせるため**の道具です。
