# 2026/8/10 ミーティング要約

## AI動画・定期実行・GitHub という土台

Masaya Kokabu × Yu Asano

---

## 今日のテーマ（5 論点）

1. **AI動画生成（Seedance）** — 実写と見分けがつかない品質へ
2. **Figma × MCP** — コメントから画像生成・配置まで自律実行
3. **定期実行の設計** — 毎週・毎朝、勝手に動く仕組み
4. **ルーティン機能** — Claudeアプリ内で定期タスクを組む
5. **GitHub を土台にする** — 無料・どこからでも・閉じても動く

---

## 1. AI動画生成はもう「実写と区別できない」

- **Seedance 2.5** クラスになると、AI動画と実写の判別が難しい水準。
- プロンプトだけで**カメラワークやトランジション**まで組み立ててくれる。
- 用途: **ショートドラマ / プロダクト紹介動画**。
- 実例: 顔写真1枚＋プロンプトで、**15秒の動画を約3分**で生成。
- コスト: **1回あたり約150円**。月額課金とペイパー課金の両方あり。
  - CapCut Pro 契約（月 900〜1,480円程度）でも複数回使える。

→ Masaya さん: **会社での契約を検討**。

---

## 1. なぜ今これを触るべきか

> 「作れるかどうか」ではなく、**「毎週何本回せるか」**が差になる。

- 撮影・編集の工程が消えるので、**試行回数**を上げられる。
- 動画は当たり外れが大きい領域 → **数を出せる側が有利**。
- 広告クリエイティブの検証サイクルと相性が良い
  （Meta広告の分析 → 仮説 → 動画生成 → 検証）。

---

## 2. モデルの使い分け（Opus / Sonnet）

| | 向いている場面 | コスト感 |
|---|---|---|
| **Opus** | より高度な推論が要る場面 | 高い |
| **Sonnet** | 人間が普通にやる範囲の作業 | 効率が良い |

- 「常に最上位」ではなく、**タスクの難易度で選ぶ**。
- Masaya さん: 直近数日 Opus を使い、**出力の精度と関連性が上がった**実感。

---

## 3. Figma × MCP で「コメント → 画像 → 配置」まで自律実行

デザイナーからの差し替えコメントを起点に、AI が最後まで走った実例。

**これまで**: 毎回プロンプトを書く → 生成 → 見比べる → ダウンロード → 配置
**これから**: コメントを残すだけ

---

## 3. ここで効いているのは「トリガー」

- 人が指示を出すのではなく、**コメントという既存の作業がトリガー**になっている。
- 自動化は「新しい操作を覚える」より、**すでにやっている行動に紐づける**と続く。
- 前回のテーマ（Skills にトリガーを付ける）と同じ話。

> 自動化の設計 = **どのイベントで発火させるか**を決めること。

---

## 4. 定期実行：勝手に動いている仕組みの例

<div class="mermaid">
graph TD
  MON["毎週月曜"] --> H["8:00 ヘルスチェック"]
  MON --> A["10:00 自動化タスク管理"]
  MON --> M["モーニングプレップ<br/>（会議議事録の収集・準備メモ作成）"]
  DAY["毎日"] --> V["参照画像200枚から<br/>動画を5本生成 → Google Driveへ"]
  H --> OB["Obsidianの蓄積ノートへ"]
  A --> OB
  M --> OB
</div>

- 全体は **Markdown と Obsidian** で管理。
- 毎週のメモ・学び・改善案が蓄積ノートに溜まり、**定期メンテナンスに反映**される。

---

## 4. サブエージェントは「必要になったら生える」

- 小タスク（メール抽出・要約・情報検索…）が複数必要になると、
  **サブエージェントが自動生成**されて分担する。
- 人が「このエージェントを作ろう」と設計しなくてよい。
- 悩みどころ: **Obsidian がデータ量で重くなってきた**
  → 一時メモリと長期保存の分離が、ここでも効いてくる。

---

## 5. Claude の「ルーティン」機能

Claude アプリ内で、**定期実行したいタスクをそのまま登録**できる。

- メールのトリアージ
- メッセージのサマリー
- ブリーフィングの作成

登録したルーティンは **Obsidian 側にも表示**される。
Claude Code を書かなくても始められるので、**最初の一歩に向いている**。

→ Masaya さん: **まずルーティンを1つ作ってみる**。

---

## 6. GitHub を土台にする理由

<div class="mermaid">
graph LR
  L["手元のPC"] -->|push| G["GitHub"]
  G --> C["クラウドで自動実行<br/>（PCを閉じてもOK）"]
  G --> P["GitHub Pages<br/>（無料で公開）"]
  G --> M["別のPCからも同じ環境"]
  C --> N["結果が通知で届く"]
  style G fill:#d7ecff,stroke:#06c

- **無料**で使える。
- **テスト環境と本番環境を分けられる**。
- 例: 毎日、新着の不動産物件情報が GitHub から通知される仕組み。

---

## 6. すでに GitHub の上に乗っている

> **この勉強ノート自身が GitHub Pages 上で動いています。**

- ドメイン取得もサーバー費用も不要。
- 複数のPCを使うなら、**GitHub がある方が圧倒的に楽**。
- 「コードを置く場所」ではなく、**自動化を走らせる土台**として捉える。
