# 2026/11/28 ミーティング要約

学習に関係する要点を抜粋

---

## 今回のポイント

1. **タスク管理アプリは古い Mac で常時動かす**（Notion ではなくローカル）
2. **多すぎるセッションは、状態を色で一目に出す**
3. **プロジェクトとスレッドで「自分待ち」を見る**
4. **広告の増額・減額の判断は、人がやる仕事ではない**
5. **定例は、Masayaさんが作り Yu が作り込む形に変える**

> 使い方は十分に身についた。次は、止まらずに動く仕組みを一緒に作る。

---

## 1. 自作のタスク管理アプリをどう動かすか

| 方法 | 良いところ | 気になるところ |
| --- | --- | --- |
| **ローカルにサーバー**（Docker など） | 無料。手間はアプリを入れる程度 | PC を動かし続ける |
| **Notion をデータベースに** | サーバー管理が要らない | 有料。普段使わないと合わない |

- **決定：使っていない古い個人 Mac を常時動かし、ローカルで運用する**
- 要るのは主に **メモリ**。カレンダー連携なら数分の遅れは問題ない
- 注意：**電源につなぎっぱなし／自動スリープを切る／空き容量を保つ**
- 持ち歩く Mac だと、外出中に同期しないのが気になりやすい

---

## 2. セッションが多すぎて、どこまで進んだか見えない

- 悩み：12ほどのセッションを画面分割で並べ、**どれがどこまで進んだか分からない**
- **オルカ**（Claude Code と Codex をまとめて扱える無料ツール）
  - トークンの余りを防ぎやすい。ただ並ぶのは **ターミナル** で、進み具合の表示は難しそう
  - Yu は GitHub Copilot で足りているため未活用。もう一度試して共有する
- 別案：自作アプリの AI 欄に、状態を **色で出す**
  - 緑＝完了、黄＝あなたの操作待ち、赤＝止まっている
  - 3台目のモニターに映しておけば、見に行かなくても分かる
- 小ネタ：Codex の既定モデルは **GPT-6.2** でよい（値段は同じ）

---

## 3. プロジェクトとスレッドで「自分待ち」を見る（Yu の運用例）

- Claude の **プロジェクト** の中にスレッドを立て、
  「自分で止まっている」「裏で動いている」が **一覧で見える** ようにしている
- **メインのセッションには、短い要約とネクストアクションだけ** を出させる
- 詳しい中身は **MD ファイルに書かせて Notion に保存**。じっくり読みたいときだけそちらを開く
- 画面（UI）を作り込むより、**出し方のルールを決める** ほうが効く
- Masayaさんの環境では、プロジェクト機能が表示されていない
  → チームプランが原因かは不明。**原因を調べる**（スレッドで自分待ちを見る運用の前提になる）

---

## 4. エージェントの使い分け（Yu の例）

| 道具 | 任せていること |
| --- | --- |
| **Grok ボット** | ゴールを決めて繰り返す仕事。LinkedIn で申請して面談を入れる、メール返信、X のリサーチ |
| **常時稼働の Claude** | 朝5時ごろ、カレンダーの **AI に任せられる予定** のリサーチと下書きを済ませる |

- 人は最後に確認するだけ。終わった予定には **「Done」** が付く
- **夜までに Done にならない予定は、翌日の空き枠へ自動で移る**
- カレンダーの操作は全部 AI がやっている

---

## 5. 広告の配分判断を、仕組みにする（最初のテーマ）

**起きていること**
- 媒体ごとの CPA が目標を少し超え、増額に踏み切れなかった
- 実際は **費用ゼロの獲得**（オーガニック等）が伸び、全体は好調 → **機会損失が2か月続く**

**作りたいもの**
- **月の序盤から**「この確率で増額したほうがよい」と知らせる仕組み
- 判断は決まった選択肢から選ぶだけ。**人が月1回しか見ないから遅れる**
- 全媒体の担当者に、**シミュレーションと増減額の指示** まで出す（**年内**）
